# Rome, bilingual cut. Italian and English, same finding, same structure.

Source: `brandgeo/web/ai-visibility-for-rome.html`. Data collected **2026-07-10**
on **four** engines: Claude, Gemini, Meta AI, Perplexity.

**Deliverables**

| File | What it is |
|---|---|
| `rome-it-silent.mp4` | Italian upload master. Zero audio streams. Pick a track in the platform's in-app library. |
| `rome-it-scored.mp4` | Same picture, BrandGEO-composed bed. Paid, site embeds, decks. |
| `rome-it-cover.png` | Literal frame 0 of the Italian master, verified byte-identical. |
| `rome-en-silent.mp4` / `rome-en-scored.mp4` / `rome-en-cover.png` | The English equivalents. |

One master serves every platform: built to the **tightest** reserve of the four
(TikTok's 200 top / 360 bottom / 200 right), which is inside Instagram's,
Facebook's and YouTube's on every edge.

## 2. The data constraint, which is the whole job

### 2.1 Engine lineup and date, as drawn

Scene 12 of both cuts is a card whose label is the collection date and whose
rows are the engines, in the reader's eyeline together:

```
COLLECTED 10 JULY 2026        RILEVATO IL 10 LUGLIO 2026
Claude                        Claude
Gemini                        Gemini
Meta AI                       Meta AI
Perplexity                    Perplexity
FOUR ENGINES RAN.             QUATTRO MOTORI.
```

Four engines, named, with the date attached. **ChatGPT appears nowhere in either
cut**, verified mechanically against the drawn bytes, not by reading. It is not
named as absent either: naming it at all would put it on screen next to this
run, which is the thing to avoid.

Today's Growth five is not claimed, implied, or counted anywhere. The only
engine count drawn is `FOUR` / `QUATTRO`, and it is bound to `10 JULY 2026` in
the same card.

### 2.2 How the 5/5 is framed so it cannot be misread

The page's `5/5` counts **restaurants from one engine across two languages**. It
is not five engines agreeing, and a five-engine consensus is arithmetically
impossible on this page because only four ran.

The cut never draws the string `5/5` at all. It draws a card that spells out
what is being counted, one term per row, and then negates the wrong reading
explicitly on the next beat:

```
WHAT THE 5 OF 5 COUNTS        COSA CONTA IL 5 SU 5
5 restaurants of 5            5 ristoranti su 5
1 engine                      1 motore
2 languages                   2 lingue

NOT FIVE ENGINES              NON CINQUE MOTORI
AGREEING.                     CHE CONCORDANO.
```

Three things make this hold rather than hope:

1. **The denominators are labelled.** `1 engine` and `2 languages` are on screen
   as separate counted terms, so the `5` cannot attach to engines.
2. **The card is up for 1.2s before the negation lands** (scene 8, then scene 9
   adds the two lines). The reader gets the correct reading first and the
   refutation second, rather than being corrected.
3. **The negation is explicit.** `NOT FIVE ENGINES / AGREEING.` names the wrong
   reading and rejects it. An earlier agent made exactly this misreading, so it
   is stated rather than left to inference.

The word `consensus` is never drawn, in either language.

### 2.3 The retired engine, said plainly

Scene 10 names Meta AI as the engine that reproduced the list. Scene 11 adds
`RETIRED SINCE.` / `OGGI È RITIRATO.` Scene 15 turns it into the closing
argument: `THE ENGINE IS GONE. / THE RECORD STAYS.` and `IL MOTORE È SPARITO. /
LA MISURA RESTA.`

That is the honest shape and it is the strongest beat in the cut. A dated
measurement outlives the thing it measured; an engine that no longer exists
cannot be re-queried, and the record is the only remaining access to what it
said. Retirement is disclosed as a fact about the instrument, not hidden and not
apologised for.

### 2.4 What is deliberately NOT on screen

- No `5/5` as a bare figure.
- No engine count other than four, and never without the date.
- No ChatGPT, Google AI Mode, Grok, Copilot, DeepSeek.
- **No measured subject.** No restaurant, hotel, agency or firm name from any
  result set. Naming the ENGINE is the point here and is allowed; naming what it
  named is not.
- No superlative. The page itself carries three (`the strongest ... anywhere in
  this research program`, `the worst extraction gap of any city tested so far`,
  `a higher gap rate than New York`). **All three were refused**, per the rule
  that a superlative cannot be verified by reading the page asserting it.
- No cross-corpus comparison of any kind. Rome's `0 brands with cross-engine
  consensus` is a real and interesting finding but the page states it as
  `unlike every prior city`, which is a universal over the corpus, so it is out.
- No pricing, no plan names. TOFU, soft CTA.

## 3. Compliance scan, and its negative controls

`scan.py` parses `textfile='...'` back out of the 32 filtergraph files handed to
ffmpeg and reads those files' bytes. It does not read `copy.py` and it does not
read this document. **128 drawn strings, 63 unique. Exit 0.**

### 3.1 The diacritic bug, fixed before it could bite

A raw-byte matcher silently passes a company name written without its diacritic.
This cut is the worst case for it: the finding IS a ranked restaurant list, so
the names that must not appear are the names the source page is full of, and
Italian names carry graves and apostrophes constantly.

Both sides of every comparison are now folded: apostrophe variants (`U+2019`,
`U+2018`, `U+02BC`, `U+00B4`, backtick, `U+201B`, `U+FF07`) to ASCII, then
NFKD, then combining marks stripped, **then** case-folded. Case-folding last is
load-bearing; folding first leaves some precomposed accented capitals intact.

### 3.2 Negative controls, all fired

```

en dash              'COSA – CONTA'           -> FIRED
minus sign           'COSA − CONTA'           -> FIRED
style word           'SEAMLESS ANSWERS.'      -> FIRED
superlative          'THE BEST ENGINE.'       -> FIRED
superlative it       'I MIGLIORI MOTORI.'     -> FIRED
forbidden engine     'ChatGPT'                -> FIRED
forbidden engine 2   'Google AI Mode'         -> FIRED

measured subjects, EVERY spelling variant constructed per name:
  'La Rosetta'                3 variants -> ALL FIRED
  'Il Pagliaccio'             3 variants -> ALL FIRED
  'La Gensola'                3 variants -> ALL FIRED
  'Il Convivio'               3 variants -> ALL FIRED
  'La Campana'                3 variants -> ALL FIRED
  'Singer Palace Hotel'       3 variants -> ALL FIRED
  "Briggs Freeman Sotheby's"  7 variants -> ALL FIRED   (both apostrophe forms)
  'Charité'                   6 variants -> ALL FIRED   (incl. Charite, CHARITE)
  'Hôtel du Petit Moulin'     7 variants -> ALL FIRED   (incl. Hotel du ...)
  "Claude's prose #1 pick"    7 variants -> ALL FIRED

restore -> clean baseline silent, no false positive
```

The accented probes are the ones that matter: `Charite` and `Hotel du Petit
Moulin`, spelled with no diacritic at all, both fire against corpus entries that
carry one. Before the fix they would have walked straight through.

### 3.3 The corpus, and a harvester bug the controls caught

**303 unique normalised names**, harvested from **result columns only** across
every `ai-visibility-for-*.html` page: `<td class="leader">` cells, prompt-card
result labels of the form `<NAME>: 3/4 engines`, and parenthesised comma lists
of three or more items inside callouts (which is where Rome's five restaurant
names live, so that source cannot be dropped).

An earlier version also swept the Rome page's whole prose for capitalised
phrases. That yielded `Rome Data Shows`, `When One Engine Repeats Itself` and
similar, whose only possible effect on a clean cut is a **false positive against
correct copy**. Dropped.

**The harvester was broken and the curated cross-check found it.** `_keep()`
rejected any candidate containing a descriptive token, matched as a SUBSTRING.
`La Rosetta` contains `set`, so the single most important name on the page was
being silently dropped from the corpus. Fixed to word-boundary matching. The
check that caught it is worth keeping: 8 names read by hand off the page, and an
assertion that the harvester finds them on its own. It now finds **7 of 8**; the
miss is `Palazzo Cinquecento`, a deliberate partial of `NH Collection Palazzo
Cinquecento`, which the harvester does find.

### 3.4 Scan result on the real drawn bytes

```
non-ASCII drawn: U+00C8 LATIN CAPITAL LETTER E WITH GRAVE   'IL MOTORE È SPARITO.', 'OGGI È RITIRATO.'
non-ASCII drawn: U+00CC LATIN CAPITAL LETTER I WITH GRAVE   'UNA LISTA COSÌ'
non-ASCII drawn: U+00E0 LATIN SMALL LETTER A WITH GRAVE     'visibilità IA, misurata'
engine names drawn: claude, gemini, meta ai, perplexity  (+ brandgeo, getbrandgeo.com)
universal-candidate flags: NONE
PASS: no banned dashes, no style words, no superlatives, no forbidden engine, no measured subject
```

**Non-ASCII is expected and correct here.** The banned codepoints are only the
five dashes (em, en, figure, minus, horizontal bar), all of which are absent.
"Zero non-ASCII" is explicitly NOT a pass condition on the Italian cut.

The universal scanner returned **no flags at all**. One line was pre-emptively
rewritten during drafting: `TUTTE E DUE LE VOLTE.` became `IN ENTRAMBI I CASI.`
`Tutte` quantifies over exactly the two measured runs and is defensible, but
`entrambi` is equally natural Italian and costs nothing, so the argument was
avoided rather than won.

## 4. Glyph rendering, verified

drawtext with a font missing a glyph renders a blank or a `.notdef` box and
exits 0, so "no error" proves nothing. Four steps, the last one on the delivered
file.

### 4.1 The failure signature, measured first

Three codepoints Inter genuinely lacks, rendered at 66pt Inter-ExtraBold:

```
U+0E000    22x74  fill 0.896  full rows 32  row runs 1
U+0E001    22x74  fill 0.896  full rows 32  row runs 1
U+10FFFD   22x74  fill 0.896  full rows 32  row runs 1
all three byte-identical

swept:  thr  11  fill 0.896  full rows 32  row runs 1
        thr  40  fill 0.808  full rows 24  row runs 1
        thr 140  fill 0.784  full rows 22  row runs 1
```

**A missing glyph is one solid run at every threshold.** That is the reference
to discriminate against, rather than a guess about what "looks wrong".

### 4.2 Each accented glyph, its OWN columns

The glyph's column band is located from prefix ink widths measured on the real
1080-wide canvas, so it is the glyph's own pixels and not the line's. A
line-level comparison is useless: swapping one character in a twenty-character
line leaves most of the line intact and scores high against anything.

```
E-grave U+00C8   'IL MOTORE È SPARITO.'    x477..510 (34px)
   thr  40  34x63  fill 0.588  full rows 18  row runs 2
   thr 140  34x63  fill 0.561  full rows  0  row runs 2
E-grave U+00C8   'OGGI È RITIRATO.'        x287..320 (34px)   same figures
I-grave U+00CC   'UNA LISTA COSÌ'          x609..625 (17px)   WORD-FINAL
   thr  40  17x63  fill 0.639  full rows  0  row runs 2
   thr 140  17x63  fill 0.585  full rows  0  row runs 2
a-grave U+00E0   'visibilità IA, misurata' x203..217 (15px)   WORD-FINAL, lowercase
   thr  40  15x24  fill 0.558  full rows  0  row runs 2
   thr 140  15x24  fill 0.464  full rows  0  row runs 2
```

The mark separates from its vowel at every threshold at or above 40, on all
four. Both **word-final graves** are tested explicitly, because that is where a
clipped or dropped mark is easiest to overlook and where it changes the word.

**One criterion had to be corrected, and the correction matters.** "Zero full
rows" is not a usable discriminator for `È`: the letter E's own three horizontal
bars span its 34px isolated band, so a correctly rendered E-grave reports 18 full
rows. Judging it by that rule would have failed a good render. The criteria
actually used, each argued against the §4.1 reference:

- **row runs >= 2** — tofu is exactly one run at every threshold
- **fill < 0.70** — tofu measures 0.78 to 0.90 at every threshold
- **not solid** — tofu is full width on most of its rows

### 4.3 On frames decoded out of the DELIVERED master

```
scene15 frame655  'IL MOTORE È SPARITO.'    thr 40 fill 0.440 runs 3  |  thr 90 fill 0.428 runs 3
scene11 frame388  'OGGI È RITIRATO.'        thr 40 fill 0.587 runs 2  |  thr 90 fill 0.561 runs 2

### 4.4 Apostrophes

```
apostrophe codepoints in the DRAWN bytes: NONE
```

The Italian was written without any apostrophe, deliberately. `L'IA` and
`non c'è più` were both considered and rejected in favour of `I MOTORI` and
`È SPARITO`, so the typographic-versus-ASCII substitution risk does not exist in
this cut rather than being managed.

platforms, so one master serves all of them. Usable box `y 200..1559`,
`x ..879`. Every number below comes from frames decoded out of the **delivered**
masters.

### 5.2 Method B, diff against a text-free control, noise floor measured

The control is a flat canvas through the **identical** encode (numbered frame
sequence at `-framerate 30`, `libx264 -preset slow -crf 18`, `-profile:v high
-level 4.0`, `yuv420p`, same frame count). The floor was measured on **all**
frames in three regions empty by design, before any threshold was chosen:

```
y1620..1919  below everything      max |delta| = 0
x900..1079   right of the type     max |delta| = 0
y0..190      above the rail        max |delta| = 0
-> diff threshold 1, one above the measured floor
```

The floor is genuinely zero here, worth stating because run 5's Facebook build
measured 7 on the same test. This canvas is flat and the ink is sparse, so x264
at crf 18 reproduces the empty regions bit-exactly. It was still measured rather
than assumed.

```
                          ITALIAN                ENGLISH
method A (gray thr 11)    x  60..832  y 250..1471   x  60..819  y 250..1471
method B (rgb, delta>1)   x  56..832  y 248..1473   x  56..819  y 248..1473
```

B runs 4px wider left and 2px taller because single-channel fringing survives an
RGB max-channel comparison and is averaged away by the gray conversion. **B is
taken wherever it is larger.** It does not touch the frame edge on any side,
which is the signature of the yuv420p row-0 artefact that produced a false
failure on run 3, so this is real ink and not a codec artefact.

### 5.3 Method C, declared rects

36 rects recorded at draw time per cut (rail track, 16 rail fills, label rules,
the logo overlay). Union `x 60..299  y 250..1399`, inside both measured boxes.
The logo overlay `y` is 980, already even, so the "overlay rounds an odd y down"
trap cannot bite and the declared rect equals the effective rect.

Nothing in this build is dark-on-dark: the dimmest element is the rail track at
luma 29 against a canvas of 10, a 19-step separation both pixel methods resolve.
Method C is therefore a redundancy here rather than the only witness, which is
the desired state.

### 5.6 The Italian set the type size, as required

Column geometry was fixed before the first render: pen `x = 100`, budget 745, so
the design right edge is 845 and 34px sits inside the 879 limit by construction.
The headline size is then **fitted by measurement, not chosen**: all 45 unique
headline lines from BOTH cuts go into one pool, each is rendered alone at 100pt,
its real ink width read off a decoded frame, and the largest size on the ladder
78/72/66/60/54 whose widest line fits 745px is taken.

```
45 lines measured
widest at 100pt   1107px   'IL MOTORE È SPARITO.'      <- an ITALIAN line
78pt -> predicted 863.5px   over budget
72pt -> predicted 797.0px   over budget
66pt -> predicted 730.6px   FITS      <- chosen
re-measured at 66pt: widest real 731px, still 'IL MOTORE È SPARITO.'
   731  'IL MOTORE È SPARITO.'      <- IT
   724  'UNA CENA DI LAVORO'        <- IT
   719  'A LIST THAT REPEATS'       <- EN
   711  'UN MOTORE HA DATO'         <- IT
   703  'NON CINQUE MOTORI'         <- IT
   700  'THE ENGINE IS GONE.'       <- EN
```

Five of the six widest lines are Italian. The Italian was budgeted first and the
English written into the size it produced, so the two cuts are visually
comparable rather than the English being set large and the Italian squeezed.

Because point-size scaling of a hinted TTF is not exactly linear, all 45 lines
were **re-rendered at 66pt and re-measured** rather than trusted to the scaling.
The pass/fail number is always the box measured out of the delivered mp4, and
that number is 832 (IT) and 819 (EN).

**A first pass at this copy did not fit.** The widest line was `THE LANGUAGE

## 6. Scene boundaries, and a detector that had to be replaced

**First attempt was wrong and looked like a render fault.** It used the scalar
INK COUNT per frame with a relative step threshold. It missed 1 to 2 boundaries
per cut, and the miss set MOVED with the threshold (IT missed 1 at thresholds
11/40/90 and 0 at 150; EN missed 1 at 40 and 2 at 11/90/150).

Per the brief's own rule, a result that comes and goes with the measurement
threshold indicts the detector, not the render. The cause is that a scalar
cannot see a picture change that preserves the pixel COUNT: EN scene 13 to 14
replaces two lines of headline with two other lines of headline of similar mass.

**Replacement: count the pixels that CHANGED between consecutive frames.** Inside
a scene the source PNG is byte-identical and only quantisation noise moves;
across a cut most of the type block moves. Frame hashing is still not used,
because identical pictures do get different quantisation noise, which is exactly
what this metric tolerates and a hash does not.

The separation was measured, not assumed, and the count threshold placed at the
geometric middle of the measured gap:

```
IT  pixel-delta thr  2:  intra-scene max 1081   at-boundary min 14468   gap 13x  -> 15/15 exact
IT  pixel-delta thr  6:  intra-scene max  447   at-boundary min 13637   gap 30x  -> 15/15 exact
IT  pixel-delta thr 12:  intra-scene max  387   at-boundary min 13583   gap 35x  -> 15/15 exact
IT  pixel-delta thr 24:  intra-scene max  326   at-boundary min 13473   gap 41x  -> 15/15 exact
EN  pixel-delta thr  2:  intra-scene max 1005   at-boundary min 12483   gap 12x  -> 15/15 exact
EN  pixel-delta thr  6:  intra-scene max  510   at-boundary min 11997   gap 23x  -> 15/15 exact
EN  pixel-delta thr 12:  intra-scene max  442   at-boundary min 11938   gap 27x  -> 15/15 exact
EN  pixel-delta thr 24:  intra-scene max  329   at-boundary min 11861   gap 36x  -> 15/15 exact
```

**All 30 boundaries land on their designed frame at all four thresholds.** The
gap is never narrower than 12x, so no threshold inside it changes the answer.

The rail is drawn as 16 static boxes per cut, because `drawbox` cannot animate on
8.1.2 (no `eval` option, `x/y/w/h` evaluated once at init, so `h='1150*t/27.6'`
would have silently frozen at its t=0 value). It moving was confirmed by
measuring the fill's bottom row on the delivered file at every scene midpoint:

```
IT designed 40 42 75 142 200 246 312 367 454 504 575 692 783 862 958 1150
IT measured 40 42 75 142 200 246 312 367 454 504 575 692 783 862 958 1150
EN designed 40 41 74 140 199 243 310 363 451 504 575 690 778 858 955 1150

## 10. Commands

Fonts are referenced by bare filename with ffmpeg's cwd set to the build folder.
This is load-bearing on Windows: a drive-letter colon inside a filtergraph option
value terminates the option even when the value is quoted, so `fontfile=C:/...`
fails to parse.

**Every string is passed by `textfile=`, not `text=`.** That removes all
filtergraph escaping questions and, more importantly, makes the scanner's input
the exact bytes ffmpeg read.

**1. Type fitter**, run before any scene is drawn. Each unique line alone on a
3200x400 canvas, ink width read off a decoded frame:

```
ffmpeg -hide_banner -loglevel error -y -f lavfi -i color=c=0x090A0F:s=3200x400 \
  -filter_complex "[0:v]drawtext=fontfile='fonts/Inter-ExtraBold.ttf':\
textfile='txt/fit12.txt':x=0:y=80:fontsize=100:fontcolor=0xE8E9ED[out]" \
  -map "[out]" -frames:v 1 -f rawvideo -pix_fmt gray -
```

**2. Scene stills**, one PNG per scene, 16 per language, filtergraph in a file:

```
ffmpeg -hide_banner -loglevel error -y \
  -f lavfi -i color=c=0x090A0F:s=1080x1920 \
  -/filter_complex scenes/g_it_09.txt -map "[out]" \
  -frames:v 1 -update 1 -pix_fmt rgb24 scenes/s_it_09.png
```

Scene 16 additionally takes `-i logo.png` and ends
`[bg];[1:v]scale=132:132[lg];[bg][lg]overlay=100:980[out]`. A representative
graph body, Italian scene 9:

```
[0:v]drawbox=x=60:y=250:w=6:h=1150:color=0x1B1D2B@1:t=fill:replace=1,
drawbox=x=60:y=250:w=6:h=454:color=0x8B5CF6@1:t=fill:replace=1,
drawtext=fontfile='fonts/Inter-Bold.ttf':textfile='txt/it_s09_99.txt':x=100:y=1448:fontsize=30:fontcolor=0xA78BFA,
drawtext=fontfile='fonts/Inter-SemiBold.ttf':textfile='txt/it_s09_00.txt':x=100:y=520:fontsize=30:fontcolor=0xA78BFA,
drawbox=x=100:y=574:w=200:h=4:color=0x7C3AED@1:t=fill:replace=1,
drawtext=fontfile='fonts/Inter-SemiBold.ttf':textfile='txt/it_s09_02.txt':x=100:y=610:fontsize=44:fontcolor=0xE8E9ED,
drawtext=fontfile='fonts/Inter-SemiBold.ttf':textfile='txt/it_s09_03.txt':x=100:y=690:fontsize=44:fontcolor=0xE8E9ED,
drawtext=fontfile='fonts/Inter-SemiBold.ttf':textfile='txt/it_s09_04.txt':x=100:y=770:fontsize=44:fontcolor=0xE8E9ED,
drawtext=fontfile='fonts/Inter-ExtraBold.ttf':textfile='txt/it_s09_05.txt':x=100:y=900:fontsize=66:fontcolor=0xA78BFA,
drawtext=fontfile='fonts/Inter-ExtraBold.ttf':textfile='txt/it_s09_06.txt':x=100:y=988:fontsize=66:fontcolor=0xA78BFA[out]
```

`replace=1` is on **every** `drawbox`. The source is opaque RGB so blending would
have worked, but run 1's vanished-at-alpha-0 violet rule is cheap enough to make
structurally impossible rather than to reason about per call. `color=black@0.0`
is not used anywhere; the base is a `color=c=0x090A0F` lavfi source.

**3. Silent master.** Each scene PNG is copied into a numbered frame sequence,
`n` copies for an `n`-frame scene, so the timeline is frame-exact by construction:

```
ffmpeg -hide_banner -loglevel error -y -framerate 30 -i frames_it/f%05d.png \
  -vf "format=yuv420p" -frames:v 828 \
  -c:v libx264 -preset slow -crf 18 -profile:v high -level 4.0 \
  -pix_fmt yuv420p -movflags +faststart -an rome-it-silent.mp4
```

`-an` is what makes this a true silent master rather than a silent audio track.

**4. Text-free control**, the same command over 828 copies of a blank canvas PNG,
so it shares every codec artefact and differs only in content.

**5. Cover**, the literal first frame:

```
ffmpeg -hide_banner -loglevel error -y -i rome-it-silent.mp4 \
  -frames:v 1 -update 1 rome-it-cover.png
```

**6. Scored cut:**

```
ffmpeg -hide_banner -loglevel error -y -i music.wav -t 27.600 \
  -af "afade=t=in:st=0:d=0.08,afade=t=out:st=26.100:d=1.5" \
  -ar 48000 -c:a pcm_s24le music_it.wav

ffmpeg -hide_banner -i music_it.wav \
  -af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json -f null -

ffmpeg -hide_banner -loglevel error -y -i music_it.wav \
  -af "loudnorm=I=-16:TP=-1.5:LRA=11:measured_I=-16.19:measured_TP=-4.41:\
measured_LRA=3.60:measured_thresh=-26.25:offset=-1.15:linear=true" \
  -ar 48000 -c:a pcm_s24le music_it_norm.wav

ffmpeg -hide_banner -loglevel error -y -i rome-it-silent.mp4 -i music_it_norm.wav \
  -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k -ar 48000 -ac 2 \
  -shortest -movflags +faststart rome-it-scored.mp4
```

**7. Verification.** Every frame is decoded sequentially in ONE pass and indexed.
`-ss` is not used to sample near a cut: seeking lands on the neighbouring scene
often enough to make a boundary check meaningless.

```
ffmpeg -hide_banner -loglevel error -i rome-it-silent.mp4 -f rawvideo -pix_fmt gray -
```

Two full decodes per language: one gray (threshold sweep, type box, scene
midpoints, rail measurement) and one rgb24 paired with the control (noise floor
and diff box at every candidate threshold in a single pass). A third gray pass
per language runs the boundary detector at four pixel-delta thresholds.
